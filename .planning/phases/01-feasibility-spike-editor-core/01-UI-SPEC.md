# Phase 1 — UI Design Contract

> Visual and interaction contract for the Phase 1 spike shell. Generated by gsd-ui-researcher.
>
> **Scope note:** Phase 1 is a developer-facing feasibility spike. The UI surface being specced here is the
> *app shell / harness* around GrapesJS — not the email canvas or MJML blocks, which are a separate styling
> world governed by `mjml-email-safety.md` and `BLOCK_DEFAULTS`. GrapesJS ships its own CSS for the canvas;
> the shell spec below covers only what wraps it.

## Spacing Scale

Standard 8-point scale. All values are multiples of 4. Source: shadcn/Tailwind defaults — no deviation for this phase.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding between tight elements |
| sm | 8px | Button internal padding, input padding |
| md | 16px | Default element spacing, panel padding |
| lg | 24px | Toolbar height inner padding, section separation |
| xl | 32px | Layout gaps between major shell zones |
| 2xl | 48px | Reserved (not used in Phase 1 harness) |
| 3xl | 64px | Reserved (not used in Phase 1 harness) |

Exceptions: GrapesJS canvas fills `100vh` minus the toolbar height. Touch targets for harness buttons: minimum 44px height to meet WCAG 2.1 AA.

## Typography

The harness shell is minimal text. Two weights only. These values follow shadcn's CSS variable defaults (Tailwind 4 CSS-first).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (regular) | 1.5 |
| Label | 12px | 400 (regular) | 1.4 |
| Heading | 16px | 600 (semibold) | 1.25 |
| Display | 20px | 600 (semibold) | 1.2 |

Declared weights: **400 (regular)** and **600 (semibold)**. No other weights.

> Only Body and Label are used in the Phase 1 harness (toolbar button labels, status messages, error
> copy). Heading/Display are declared for consistency with the forward-compatible design system;
> Phase 1 does not use them.

## Color

Shell colors use shadcn CSS variables, NOT email palette hex values. The DDROIDD email palette
(`#0B1624` navy, `#F45E43` orange, `#ffffff` text) belongs exclusively to `BLOCK_DEFAULTS` in the
email/MJML world and must never appear in shell Tailwind classes.

| Role | CSS Variable | Tailwind Class | Usage |
|------|-------------|----------------|-------|
| Dominant (60%) | `--background` | `bg-background` | App shell background, page surface |
| Secondary (30%) | `--card` / `--muted` | `bg-card`, `bg-muted` | Toolbar surface, panel backgrounds |
| Accent (10%) | `--primary` | `bg-primary`, `text-primary` | CTA buttons only (Save Draft, Compile Email) |
| Destructive | `--destructive` | `bg-destructive` | Not used in Phase 1 harness |

Accent (`--primary`) reserved for: "Save Draft" button, "Compile Email" button. No other elements.

> Phase 1 is a developer harness. No destructive actions (delete, discard) are scoped. Destructive
> color is declared here for completeness but the Destructive confirmation pattern is deferred to
> Phase 2 where newsletter delete is introduced.

## Shell Layout Contract

Phase 1 renders a single-route app. No navigation, no list, no login. The shell has two zones.

**Primary visual anchor:** the GrapesJS canvas (full-viewport fill below the toolbar). The toolbar is a slim secondary surface; the canvas is where the eye goes and where all editing happens.

> **Design decision note:** Spike operations (save/load/compile) are exposed as toolbar buttons, not
> console-only commands. This is a forward-investment choice per D-01 ("foundation code Phase 2
> builds on") — the toolbar zone and button components are reused in Phase 2. The spike itself does
> not *require* a toolbar; console calls alone satisfy the exit criteria. The buttons are chosen
> because they cost one shadcn Button component and produce reusable shell structure.

```
+----------------------------------------------+
| Toolbar (fixed height: 52px)                 |
|  [Save Draft]  [Load Draft]  [Compile Email]  [status text] |
+----------------------------------------------+
| GrapesJS Canvas (fills remaining viewport)   |
|  height: calc(100vh - 52px)                  |
|  GrapesJS owns all internal layout           |
+----------------------------------------------+
```

- Toolbar: `bg-card` surface, 1px bottom border (`border-b`), flex row, `gap-sm` (8px) between buttons, `px-md` (16px) horizontal padding.
- Status text: body 14px, `text-muted-foreground`, positioned after the buttons, left-aligned; shows last action result or compile error inline.
- GrapesJS Canvas: `flex-1`, no shell padding, no shell margin. GrapesJS supplies its own panel/canvas CSS via `grapesjs/dist/css/grapes.min.css`.
- Error display: compile errors appear in the status text area as body copy with `text-destructive`. No modal, no toast — this is a developer harness; inline text is sufficient.

## Interaction States

### Buttons

| State | Visual |
|-------|--------|
| Default | `variant="default"` for Save Draft / Compile Email; `variant="outline"` for Load Draft |
| Hover | shadcn default hover (handled by primitive) |
| Disabled | `disabled` attribute while a compile request is in-flight; opacity 50% via shadcn default |
| Loading (Compile) | Disable button + show "Compiling..." in status text. No spinner in Phase 1 harness. |

### Compile Error

When `/api/compile` returns errors in the `errors` array, or when the request fails:
- Status text changes to "Compile failed: {first error message from response.errors[]}"
- Text uses `text-destructive` class
- No toast, no modal — inline status text only
