## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, inline spacing |
| sm | 8px | Button internal padding (vertical), card gap, tag gap |
| md | 16px | Default element margin, form field gap, card body padding |
| lg | 24px | Section padding, dialog body padding |
| xl | 32px | Dashboard grid gap, page section gap |
| 2xl | 48px | Page-level vertical padding (top of main content area) |
| 3xl | 64px | Not used in Phase 2 surfaces |

Exceptions:
- Touch targets (icon buttons in the dashboard card menu): minimum 44px hit area via `p-3` (12px padding around 24px icon = 48px hit area; exceeds 44px min, multiple of 4)
- Asset library image grid cells: 120px × 120px fixed size (not on the 8-point scale — content-driven)
- Top nav height: 56px (`h-14`) — Tailwind default, ×4 compliant

## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 14px | 400 (regular) | 1.5 | Form labels, card metadata, nav items, table cells, timestamps |
| Label | 14px | 600 (semibold) | 1.5 | Input labels (`FormLabel`), section headings in dialogs, badge text |
| Heading | 20px | 600 (semibold) | 1.2 | Page title ("Newsletters"), dialog titles, empty-state heading |
| Display | 28px | 600 (semibold) | 1.2 | Login page brand heading only |

**Rules:**
- Exactly 2 weights in use: 400 (regular) and 600 (semibold).
- shadcn ships Button, Tabs, and FormLabel at `font-medium` (500) by default. The executor must override these to `font-semibold` (600) to match this contract. Apply via the shadcn component's `className` prop at the feature-component level — do not fork `components/ui/` files.
- Body and Label share the same size (14px) — weight is the only distinction.
- Font stack: `Inter, ui-sans-serif, system-ui, -apple-system, sans-serif` (shadcn `font-sans` variable).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f8fafc` (slate-50) | Page background, main content area, form backgrounds |
| Secondary (30%) | `#ffffff` | Cards, nav background, dialog surface, input backgrounds |
| Accent (10%) | `#F45E43` | See reserved-for list below |
| Destructive | `#dc2626` (red-600) | No destructive actions in Phase 2; reserved for upload error alerts and future phase (delete) |

**Accent (`#F45E43`) reserved for — explicit list, nothing else:**
1. Primary CTA buttons: "New Newsletter", "Log in", "Save Newsletter" when dirty (unsaved changes)
2. The DDROIDD brand wordmark/logo mark in the top nav

**Save button dirty-state clarification:** When dirty, the Save button uses accent as its **background** (filled variant), not just an outline/ring. This is the Interaction States definition — the accent-as-ring phrasing is removed from this Color list to avoid contradiction. Clean state uses `variant="outline"` with no accent.

**Secondary semantic colors (not accent):**
- `#1e293b` (slate-800): nav text, primary body text on white surfaces
- `#64748b` (slate-500): secondary/muted text (newsletter card subtitle, timestamps, empty-state body)
- `#e2e8f0` (slate-200): dividers, card borders, input borders
- `#fcd34d` (amber-300): brand gold — NOT used in the shell (email-only; excluded per two-worlds rule)

**Brand color rationale:** `#F45E43` is pulled directly from `BLOCK_DEFAULTS.accentColor` and the spike toolbar Compile button — the single DDROIDD brand identity color that bridges email and shell. `#0B1624` navy is the email canvas dark surface; the shell uses light-mode slate surfaces for legibility on a dashboard.

## Visual Hierarchy & Focal Points

Each primary screen has exactly one accent-colored focal point to draw the eye:

- **Login page primary focal point:** the "Log in" accent button (only accent element on the screen).
- **Dashboard primary focal point:** the "New Newsletter" accent CTA in the page heading row (and the empty-state CTA when the list is empty).
- **Editor toolbar focal point:** the "Save Newsletter" button when dirty (accent fill draws attention to unsaved work).
- **Asset library dialog focal point:** the "Insert" accent button, activated once an image is selected.

The 10% accent budget is spent on these focal points only — no competing accent elements per screen.

## Surface Layouts

### Login page
- Centered card, max-width 400px, on a `bg-slate-50` full-viewport background.
- Card contains: DDROIDD logo/wordmark (top, with `#F45E43` accent mark), Display-size heading "Log in to DDROIDD Newsletter Builder", email input, password input, "Log in" button (full-width, accent `#F45E43` background), Alert below button (login error only — hidden when clean).
- No public signup link, no "Forgot password" (backend-seeded accounts per D-03).

### Top navigation (authenticated shell)
- Fixed top bar, full width, `bg-white` with `border-b border-slate-200` separator.
- Left: DDROIDD wordmark + "Newsletter Builder" Label text.
- Right: Avatar with user initials → DropdownMenu with "Log out" item only.
- Height: 56px (`h-14`).

### Dashboard / newsletter list (main content)
- `bg-slate-50` page background, `pt-12` (48px) top padding below nav.
- Page heading row: Heading-size "Newsletters" left-aligned + "New Newsletter" Button (accent background, right-aligned).
- Newsletter grid: responsive CSS grid, 3 columns on ≥1280px, 2 columns on ≥768px, 1 column on mobile. Gap: 24px (`gap-6`).
- Each newsletter card: `bg-white`, rounded, border `border-slate-200`, padding 16px. Contains: thumbnail placeholder (grey rect, 16:9 aspect, `bg-slate-100`), newsletter title (Label weight, 14px semibold), last-saved timestamp (Body muted, 14px regular), "..." DropdownMenu (open, duplicate).
- Empty state: centered in the grid area — Heading "No newsletters yet", Body "Create your first newsletter to get started.", "New Newsletter" Button (accent).
- Loading state: 6 Skeleton cards matching card dimensions.

### Asset library panel
- Implemented as a Dialog (modal). Trigger: "Insert Image" action in editor toolbar or image block interaction.
- Dialog: max-width 720px, two Tabs: "Brand Assets" and "Uploaded".
- Each tab: ScrollArea containing a 4-column image grid. Each cell: 120×120px image thumbnail, object-fit cover, `rounded`, `border`, accent ring on selection hover.
- Below grid in "Uploaded" tab: "Upload image" Button. File input accepts `image/png,image/jpeg,image/gif,image/webp`. Size cap 5MB enforced server-side; client shows Sonner error toast if validation fails.
- Selecting an image: click to highlight (ring `#F45E43`), confirm via "Insert" Button (accent). "Cancel" Button (outline) closes dialog.

## Interaction States

### Save button (dirty-state tracking — D-05)
- **Clean / just-saved:** `variant="outline"` label "Save Newsletter", no accent. Signals no pending changes.
- **Dirty (unsaved changes):** `variant="default"` with accent background `#F45E43`, label "Save Newsletter". Signals action needed.
- **Saving (in-flight):** disabled, `variant="default"` accent, spinner icon inline, label "Saving…".
- **Save failed:** reverts to dirty state. Sonner error toast: "Save failed. Please try again."

### 409 Conflict (D-04)
- Save request returns 409.
- Sonner toast (destructive variant): "A newer version exists. Reload to get the latest changes." with "Reload" action.
- "Reload" action calls `loadProjectData` from server, discards local changes, clears dirty state.

### Upload flow (asset library)
- File selected → client-side size check (>5MB shows immediate Sonner error, no POST).
- POST to `/api/assets/upload` with `credentials: 'include'` + CSRF header (see `security.md`, `api-client.md`).
- Progress bar shown during upload.
- On success: new image appears in "Uploaded" tab grid, highlighted/selected, ready to insert.
- On server error (wrong type / too large / hardening failure): Sonner error toast with appropriate copy.

### Authentication flow
- Unauthenticated route access → react-router guard redirects to `/login`.
- Successful login → redirect to `/` (dashboard).
- Log out → POST `/api/auth/logout` clears cookie → redirect to `/login`.
- 401 from any API call → redirect to `/login` (the `lib/api` wrapper handles this centrally).
