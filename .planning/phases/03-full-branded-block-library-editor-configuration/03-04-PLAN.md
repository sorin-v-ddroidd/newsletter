<interfaces>
Verified from RESEARCH (source-checked against grapesjs-mjml@1.0.8):
- mj-body defaults include 'style-default': { width: '600px' } and stylable: ['width','background-color'].
  It is already selectable and already round-trips via getProjectData/loadProjectData. getHtml
  serializes style+style-default into attributes, and an untouched width (== style-default) is omitted
  from output. buildFullMjml (app/shared/mjml-head.ts) only rewrites mj-head — it never touches mj-body
  attributes, so a user width survives compile on both server (mjml) and client (mjml-browser) paths.
- mj-body is NOT in STYLABLE_BY_TYPE in editorConfig.ts today, so the property is undiscoverable.

Approach (all four resolutions locked by advisor review):
1. editorConfig.ts: add 'mj-body': ['width'] to STYLABLE_BY_TYPE. Deliberately OMIT 'background-color'
   (WIDTH ONLY this round — no global color control).
2. actions.ts: add getMessageWidth(editor) and setMessageWidth(editor, px) using the depth-agnostic
   recursive findMjBody walk (walk editor.getWrapper() for tagName === 'mj-body'; do NOT hardcode a depth
   index — RESEARCH Open Question 2). getMessageWidth parses mjBody.getStyle().width, falling back to 600.
   setMessageWidth clamps px to [320,900] then mjBody.addStyle({ width: `${clamped}px` }).
3. panelControls.tsx: add ONE shared clamped WidthRangeField control (range or number input, min 320
   max 900, default 600) that clamps in its onChange before writing. This is the single width behavior.
4. RightPanel.tsx: Pitfall 5 — the generic renderLayout() width PairedField would otherwise show an
   UNCLAMPED width when mj-body is selected. Resolution: use the shared clamped WidthRangeField for
   mj-body (key off selected.get('tagName') === 'mj-body'); do NOT leave two divergent width controls.
5. TopBar.tsx: add a Global Settings entry point (a gear item or a small popover; reuse the existing
   DropdownMenu overflow or add a dedicated popover) that renders the shared WidthRangeField bound to
   getMessageWidth/setMessageWidth. TopBar accesses the editor the same way its handlers already do
   (window.__ddroiddEditor via useEditorActions / actions layer) — keep actions.ts free of React.

Do NOT create a parallel "global settings" JSON blob — mj-body style.width is the single source of truth
(RESEARCH Don't Hand-Roll). Clamp lives in the control + setMessageWidth (the MJML property has no min/max).
</interfaces>
