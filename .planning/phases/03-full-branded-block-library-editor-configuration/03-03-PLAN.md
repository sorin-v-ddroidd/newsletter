EDIT-07 (from the ready iw7 plan — fold in, do not duplicate):
- grapesjs-mjml registers `mj-raw` as a Block Manager entry with id exactly `'mj-raw'`.
- Blocks register during plugin init, BEFORE `onEditor` runs. Remove in `onEditor`, next to the
  existing `devices-c` panel removal, guarded: if editor.Blocks.get('mj-raw') then
  editor.Blocks.remove('mj-raw') (idempotent under StrictMode double-invocation).
- LeftSidebar reads blocks live from BlocksProvider/mapCategoryBlocks -> removing from the Block
  Manager removes it from the custom panel automatically. Do NOT filter in LeftSidebar. Keep
  resetBlocks:false (it preserves the generic Text/Image/Button/Columns/Divider/Spacer blocks).
- RESEARCH confirmed no other raw surface exists: no Panels.add/commands.add for a code view,
  no MJML-import UI in TopBar/LeftSidebar/RightPanel. EDIT-07 remaining work = the removal + a
  look-and-confirm that no code/view-source affordance exists.

EDIT-08 colors (panelControls.tsx SwatchRow, currently free-form):
- SwatchRow today renders a native color input (free-form OS picker) + a free-text hex Input.
  Both must go. Replace with a constrained control: one swatch button per BLOCK_DEFAULTS color --
  backgroundColor (#0B1624), accentColor (#F45E43), textColor (#ffffff) -- each calling
  prop.upValue(hex) on click, highlighting the active value (case-insensitive compare of
  String(prop.getValue()) against each candidate). Import BLOCK_DEFAULTS from './blocks/BLOCK_DEFAULTS'
  -- the SINGLE source of truth (no parallel palette constant, locked decision).
- SwatchRow is used by RightPanel for background-color, container-background-color, color, and
  border-color. The constrained control must work for all four (it reads/writes the passed prop
  generically). Keep the exported name SwatchRow (or rename and update all RightPanel call sites)
  so RightPanel keeps compiling.

EDIT-08 fonts (editorConfig.ts styleManagerSectors, typography sector):
- The font-family entry is currently the bare string 'font-family', so GrapesJS falls back to its
  built-in property whose options are generic web-safe stacks (Arial, Times New Roman, ...). That is
  the actual gap -- a user can pick off-brand fonts.
- Replace the bare 'font-family' string in the typography sector with an explicit property object of
  type 'select', default BLOCK_DEFAULTS.fontFamily, and options = a single entry
  { id: BLOCK_DEFAULTS.fontFamily, label: 'Brand font' }. BLOCK_DEFAULTS is already imported in
  editorConfig.ts. Single approved stack -> single option (RESEARCH A2). Renders via the existing
  SelectField (RightPanel Typography) unchanged.
- Do NOT change the EMAIL_SAFE_STYLE_PROPS derivation -- it reads prop.property ?? prop.id, so the
  object form still contributes 'font-family' to the allowlist. Confirm it still does.
