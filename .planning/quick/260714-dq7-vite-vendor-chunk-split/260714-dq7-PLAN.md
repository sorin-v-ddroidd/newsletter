# Quick Task 260714-dq7: Vite vendor chunk splitting

## Problem

Production build emits a single `NewsletterEditor-*.js` chunk of **3.66MB** (1.03MB gzip).
It bundles three heavy libs together:

| Dep | ~raw | Role |
|-----|------|------|
| `mjml-browser` | 1.3MB | MJML→HTML compile (canvas render + export) |
| `grapesjs` | 1.1MB | editor engine |
| `grapesjs-mjml` | 1.2MB | MJML component model |

Total size is intrinsic (client-side MJML editor floor ≈ 1MB gzip) — **cannot be reduced**.
The `>500kB` warning is default noise for a bundled editor.

## Goal

Split the monolith into per-library vendor chunks so:
- grapesjs (rarely changes) is cached across deploys → repeat editor opens re-download only app code
- chunks download in parallel on first open
- silence the misleading size warning (raise limit, not disable)

Not a size reduction — a **caching + honesty** change. No functional change.

## Task 1 — Add build config to vite.config.ts

- **File:** `app/client/vite.config.ts`
- **Action:** Add a `build` block with `chunkSizeWarningLimit: 1500` and
  `rollupOptions.output.manualChunks` mapping `grapesjs`, `mjml-browser`,
  `grapesjs-mjml` each to their own named chunk. (rolldown-vite honors `manualChunks`.)
- **Verify:** `npx vite build` — three separate `grapesjs-*.js`, `mjml-browser-*.js`,
  `grapesjs-mjml-*.js` chunks appear; no single 3MB+ chunk; warning gone.
- **Done:** build succeeds, chunks split, entry chunk unchanged (~232KB).

## must_haves

- truths: total editor payload unchanged (split ≠ shrink); no source/runtime change
- artifacts: `app/client/vite.config.ts` build block
- key_links: `app/client/src/App.tsx` (lazy editor), `app/client/src/lib/compile.ts` (mjml-browser)

## Out of scope

- Moving compile server-side (grapesjs-mjml needs mjml-browser for canvas anyway → zero win)
- Removing mjml-browser (needed live)
- Auto-commit (project no-commit.md rule)
