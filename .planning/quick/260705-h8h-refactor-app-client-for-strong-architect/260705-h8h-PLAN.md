<objective>
Refactor `app/client` for a stronger, behavior-preserving architecture: pull GrapesJS
wiring and action logic out of the monolithic `editor/editorOptions.ts` into cohesive
service/setup modules, relocate block definitions under `editor/blocks/` per the
`react-patterns.md` folder convention, code-split the editor with `React.lazy` + a sized
`Suspense` skeleton, and wrap the editor in a reusable `ErrorBoundary`.

Purpose: Separation of concerns (logic out of UI), SOLID-friendly module boundaries,
faster initial load (editor chunk off the critical path), and crash isolation — while
keeping the currently-working editor byte-for-byte behaviorally identical.

Output: reorganized `editor/` module tree, lazy-loaded editor, `ErrorBoundary`, and a
clean `App.tsx` composition where a future auth-guard/route wrapper slots in.
</objective>

BEHAVIOR-PRESERVING REFACTOR. This is structural only. Do not change runtime behavior,
values, or ordering. This codebase has documented runtime-only failures that pass every

clobbering sectors in onReady) — a green typecheck is necessary but NOT sufficient proof.

Load-bearing invariants that MUST be preserved verbatim when code moves:
- `usePlugin(grapesjsMjml, { resetBlocks:false, resetDevices:false, resetStyleManager:false })`
  — passed via `plugins: [...]`, NOT `pluginsOpts`.
- `storageManager: false`, `height: '100%'`, and the full `styleManager.sectors` object.
- The exact operation ORDER inside `onEditor`: (1) expose `window.__ddroiddEditor` +
  `window.__ddroiddAssertRoundTrip`, (2) empty-canvas scaffold seed

  `StyleManager.getSectors().reset(styleManagerSectors)`, (4) `component:selected` →
  set per-instance `stylable` from `STYLABLE_BY_TYPE`, (5) remove `devices-c` panel,
  (6) block registration (now via `registerBlocks(editor)`).
- `EMAIL_SAFE_STYLE_PROPS` is derived FROM `styleManagerSectors` — they stay in the same
