Remove the `mj-raw` block from the editor's Blocks panel to enforce the EDIT-07 guardrail (no raw-HTML escape hatch). `mj-raw` renders arbitrary HTML that is not editable through the grapesjs-mjml UI, so it is a dead end for non-developer users and a way to bypass email-safe blocks.

Purpose: Enforce EDIT-07 — a non-dev must not reach raw markup.
Output: `mj-raw` no longer registered as a droppable block; every other block unaffected.
</objective>

<interfaces>
Verified facts from grapesjs-mjml@1.0.8 (node_modules/grapesjs-mjml/dist/index.js):
- The plugin registers its default blocks from the array:
  ['mj-1-column','mj-2-columns','mj-3-columns','mj-text','mj-button','mj-image','mj-divider','mj-social-group','mj-social-element','mj-spacer','mj-navbar','mj-navbar-link','mj-hero','mj-wrapper','mj-raw']
  Each is added to the Block Manager with an ID equal to its string — so the raw block's ID is exactly `'mj-raw'`.
- Blocks are registered during plugin init, which completes BEFORE `onEditor` runs (@grapesjs/react calls `onEditor` post-init). This is the same lifecycle window already used in editorConfig.ts to remove the plugin's `devices-c` panel and to seed the mj-body scaffold — so removal here is proven to fire after registration.
- GrapesJS 0.22.16 exposes `editor.Blocks.remove(id)` (BlockManager). Removing a block only removes the panel entry; it does not touch already-persisted project JSON, so round-trip is unaffected.

The custom LeftSidebar renders blocks from `BlocksProvider` / `mapCategoryBlocks` (the live Block Manager state), so removing the block from the Block Manager removes it from the custom panel automatically — no LeftSidebar change needed.
</interfaces>
