# Quick Task 260710-67u: Anchors inside text inherit brand color — Summary

## What changed

Naked `<a>` typed inside an `mj-text` now renders on-brand instead of link-blue, on both
surfaces, with **zero manual styling**. Scope was color only (font-size/line-height already
inherit into `<a>`).

### 1. Export — `app/server/src/services/compile.ts`
Added a second `mj-style` to `CANONICAL_HEAD`:
```
<mj-style inline="inline">a { color: #ffffff; text-decoration: underline; }</mj-style>
```
`inline="inline"` → juice inlines it onto matching `<a>` at compile (Gmail strips head
`<style>`). Type-selector specificity (0,0,0,1) loses to any existing inline color (1,0,0,0),
so branded-anchor colors and `mj-button` / `mj-social-element` anchor colors are untouched —
only naked anchors get `#ffffff`. Explicit white (not `inherit`) because Outlook's Word engine
ignores `color:inherit` on `<a>`. Extended the head doc comment to explain this.

### 2. Canvas — `app/client/src/editor/editorConfig.ts` (`onEditor`)
On `editor.on('load')`, inject `<style id="ddroidd-canvas-anchor-style">a{color:inherit}</style>`
straight into the canvas iframe document head. DOM-direct (not StyleManager/CssComposer/
`setStyle`) so it never enters `getProjectData()` — round-trip stays byte-identical. Idempotent
via id guard (StrictMode/reload safe). `inherit` is correct on the canvas (Chrome honors it;
adapts to any section's text color).

### 3. Gate — `app/server/scripts/verify-compile.ts`
Added fixture 3: compiles a doc with one naked `<a>` and one self-colored (`#ff0000`) `<a>`,
asserts naked → inline `color:#ffffff`, colored → keeps `#ff0000`. Proves fix + no clobber.

  already invisible; anchors now just match that existing behavior.
