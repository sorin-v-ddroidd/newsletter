# Quick Task 260710-67u: Anchors inside text inherit brand color

## Problem

Adding an anchor (`<a>`) inline inside an `mj-text` element forces manual styling —
color, and perceived font-size/line-height — every time. UA styles paint links blue,
so a freshly-typed link is off-brand until the user hand-types `color: ...` on it.

Root cause: `<a>` **color does not inherit** in email clients (browser + Outlook Word
engine force link-blue). That is why every existing branded block anchor hardcodes
`color: ${D.textColor}` (`hiring.ts:82/86`, `initiatives.ts:61`, `want-to-know-more.ts:53`).
There is **no global anchor rule** anywhere, so any new anchor the user adds is naked.

Scope is **color only**. `font-size` / `line-height` already inherit into `<a>` — proof:
no existing block anchor sets them. The user over-generalized from the color symptom.

Two rendering surfaces both show the naked link:
- **Export** — `compile.ts` CANONICAL_HEAD governs the downloaded HTML.
- **Canvas** — mjml-browser renders the editing iframe and never sees CANONICAL_HEAD
  (same gap the font task 260707-j0a documented).

## Approach

### 1. Export — `app/server/src/services/compile.ts` (EXPORT-04)

Add a second `mj-style` with `inline="inline"` to `CANONICAL_HEAD`:

```
<mj-style inline="inline">a { color: #ffffff; text-decoration: underline; }</mj-style>
```

- `inline="inline"` → juice inlines the rule onto matching `<a>` at compile time.
  Required because Gmail strips `<style>` (the existing `.tracking-pixel` head rule is
  the display:none exception, not a precedent for anchors).
- **No regression** — juice inlines a type-selector (`a`, specificity 0,0,0,1) only where
  no higher-specificity inline style already sits. Existing branded-anchor inline colors,
  and the inline `color` mjml renders onto `mj-button` / `mj-social-element` anchors, are
  inline styles (1,0,0,0) → they WIN. Only *naked* anchors get `#ffffff`.
- Explicit `#ffffff`, NOT `color: inherit` — Outlook's Word engine ignores `inherit` on
  `<a>` and falls back to blue (`mjml-email-safety.md`: Outlook is the #1 constraint).

### 2. Canvas — `app/client/src/editor/editorConfig.ts` `onEditor`

Inject a `<style>a { color: inherit; }</style>` into the canvas iframe document on
`editor.on('load')`:

- DOM-direct append into `editor.Canvas.getDocument().head` — deliberately NOT via
  StyleManager / CssComposer / `setStyle`, so it never enters `getProjectData()` and the
  Phase-1 round-trip stays byte-identical (`assertRoundTrip`, `actions.ts`). Same
  discipline as the font task: canvas-visual only.
- Idempotent — guard by element id so StrictMode double-invoke / reloads don't stack.
- `color: inherit` is correct here: the canvas is Chrome (honors inherit) and it adapts to
  whatever text color the parent `mj-text` carries — dark-on-light sections included, so
  the canvas has no white-on-white surprise even though export uses explicit white.

## Tasks

1. Add the inlined anchor `mj-style` to `CANONICAL_HEAD` in `compile.ts`.
2. Wire the `editor.on('load')` canvas anchor-style injection into `editorConfig.ts` `onEditor`.

## Done when

- Export: compiling MJML whose `mj-text` contains a naked `<a>` yields that anchor with an
  inline `color:#ffffff` in the HTML; a block anchor that sets its own color is unchanged;
  `mj-button` text color is unchanged.
- Canvas: a newly-typed anchor renders in the surrounding text color (not blue) without any
  manual styling.
- Round-trip stays byte-identical; `tsc` + server verify-compile clean.

## Verify

- Server: `npx tsx app/server/scripts/verify-compile.ts` (or add a compile assertion) —
  compile a doc with a naked anchor, assert `color:#ffffff` inlined on the `<a>` and that a
  pre-colored anchor keeps its own color.
- Canvas (manual, real editor): type a link inside a text block → it matches text color.
- Regression: `window.__ddroiddAssertRoundTrip()` still logs `Round-trip identical: true`.
- Real-client gate (EXPORT-04): recompile + preview in Outlook + Gmail per
  `mjml-email-safety.md` — a passing compile is not proof.

## Notes / caveats

- White-default-text trap: a naked anchor in a light-background section exports white-on-white.
  This is NOT a new trap — the head already defaults `mj-text` color to `#ffffff`, so naked
  text there is already invisible; anchors now match that existing behavior. No net change.
