# Quick Task 260706-d79 Summary: Layers panel per-layer hide/show + delete

## What was built

Per-layer eye (hide/show) and trash (delete) controls on the Layers panel, Figma-style,
respecting component locking (`removable !== false`) and email-export safety (hidden layers
never ship in the exported HTML).

## Task 1: Export-exclusion helper + visibility hook (logic layer)

- **`app/client/src/editor/actions.ts`**
  - Added `collectHidden(editor, component, hidden)` — recursive tree walk collecting every
    component where `editor.Layers.isVisible(c) === false`.
  - Added `getExportMjml(editor: GrapesEditor): string` — the single source of truth for MJML
    sent to the compiler/download. Fast path returns `editor.getHtml()` unchanged when nothing
    is hidden. Otherwise: snapshots `editor.getProjectData()`, removes hidden components inside
    `try { ... } finally { editor.loadProjectData(snapshot); }`, calls `getHtml()` inside the
    `try`. The `finally` restores the user's document (including hidden sections + their hidden
    state) even if `getHtml()` throws.
  - Rationale comment included per plan: `display:none` is not MJML-native and Outlook (Word
    engine) does not reliably honor it, so hidden sections are physically removed at export time
    rather than shipped as `display:none`.
  - Rewired both `compileDraft` and `exportHtml` to call `getExportMjml(editor)` instead of
    `editor.getHtml()` directly — canvas === export on both paths.
  - Fixed a type issue: `editor.getWrapper()` can return `undefined` per grapesjs typedefs;
    guarded with an `if (wrapper)` check before traversal (not in the original plan pseudocode,
    but required for `tsc --noEmit` to pass — no behavior change, wrapper is always defined once
    the editor is mounted).

- **`app/client/src/editor/hooks/useLayerVisibility.ts`** (new)
  - `useLayerVisibility(component: Component): { visible, toggle }`.
  - Mirrors `useSelectedComponent.ts` exactly: `useState` seeded from
    `editor.Layers.isVisible(component)`, `useEffect` subscribing to the `'component:toggled'`
    event (fired by `editor.Layers.setVisible`) to re-read and update state, cleanup via
    `editor.off`.
  - `toggle()` calls `editor.Layers.setVisible(component, !editor.Layers.isVisible(component))`.
  - React-only file; `actions.ts` stays React-free per project rule.

## Task 2: Eye + trash controls on LayerItem rows

- **`app/client/src/editor/LeftSidebar.tsx`**
  - Imported `Eye`, `EyeOff`, `Trash2` from `lucide-react` and `useLayerVisibility`.
  - `LayerItem` now computes: `isRoot` (depth === 0), `tag` (tagName/type), `isStructural`
    (root or `mjml`/`mj-body`), `canDelete` (`removable !== false`), and calls
    `useLayerVisibility(component)` unconditionally at the top of the component.
  - Row restructured into a `group flex items-center` wrapper containing the existing select
    button (now `flex-1`, dims to `opacity-60` when hidden) plus a `renderControls()` block
    (render-function extraction per code-style.md) that returns `null` for structural rows.
  - Controls: eye button (`Eye`/`EyeOff` icon depending on `visible`, `stopPropagation` so it
    doesn't also select, `aria-label` "Show layer"/"Hide layer"); trash button rendered only
    when `canDelete`, calls `component.remove()`, `stopPropagation`, `aria-label` "Delete layer",
    destructive hover color.
  - Controls fade in via `opacity-0 group-hover:opacity-100`, forced visible when the row is
    selected or hidden (`isSelected || !visible`) so a hidden row stays discoverable.
  - No inline styles added beyond the pre-existing depth-based `paddingLeft` (styling.md-
    compliant).

were **not** run by this executor:

1. Empirical round-trip gate: `editor.Layers.setVisible(cmp, false)` → confirm
   `display:"none"` appears in `editor.getProjectData()` JSON, and the hidden state survives a
   `getProjectData()` → `loadProjectData()` cycle. (This is the documented fallback-trigger gate
   — if it fails, native `setVisible` persistence must be replaced with a custom attribute-based
   flag. Not verified here.)
2. Visual: hover a layer row → eye + trash fade in; click eye → canvas section hides/reappears,
   icon flips, row dims.
3. Trash button removes the row and its canvas node.
4. Locked-row guard: setting `removable: false` on a component via console hides the trash
   button but keeps the eye.
5. Root wrapper / `mj-body` rows show no controls.
6. Export with one section hidden → hidden section absent from downloaded HTML; canvas
   unchanged (restored) after export.

These are exactly the checks the plan assigns to human/Playwright verification after the
executor returns — flagging them explicitly rather than claiming they passed.
