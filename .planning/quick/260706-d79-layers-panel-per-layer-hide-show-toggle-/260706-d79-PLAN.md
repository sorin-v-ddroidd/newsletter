<design_decisions>
## Hidden semantics (documented — this is the load-bearing choice)

"Hidden" (eye off) means: **the layer is hidden in the canvas AND excluded from the exported
HTML.** Canvas === export. No surprises.

- **Canvas hide + persistence:** use GrapesJS native `editor.Layers.setVisible(cmp, false)`.
  It writes `display:none` as a base-media component style, which (a) hides it in the canvas
  iframe immediately and (b) round-trips through project JSON for free.
- **Export exclusion (NOT display:none in the shipped HTML):** `display:none` is not an
  MJML-native attribute and Outlook (Word engine) does not reliably honor it — a "hidden"
  section could still render in a recipient's inbox. So at export time hidden components are
  REMOVED from the tree before `getHtml()` and restored immediately after. This guarantees the
  exported email matches the canvas. (See mjml-email-safety.md: only MJML-native, table-based
  output is client-safe; raw CSS display cannot be trusted.)

## Locking (BLOCK-03) safety
- **Delete** is gated: render the trash button only when `component.get('removable') !== false`.
- **Hide** is intentionally allowed on all non-root layers, including branded sections — hiding
  is non-destructive (state is reversible + persisted) so it does not violate structural locks.
- No branded block sets `removable:false` today, so the locked-delete path is present but not
  exercised by a real fixture yet (BLOCK-03 not landed). Task 2 verifies the guard via a live
  console override; treat it as "guard correct, awaiting real locked blocks."

## Root / structural rows
- No eye/trash on the root wrapper (depth 0) or on structural types (`mjml`, `mj-body`) — they
  are not user content.

## Depth
- Hide/delete are offered at any depth. Hiding the sole column/image inside a section can produce
  an "empty parent" MJML compile warning at export — that is acceptable and already surfaced to
  the user by the existing compile-warning banner (Export HTML quick task 260705-htv). Do not
  add special-case suppression.
</design_decisions>

1. In actions.ts add `getExportMjml(editor: GrapesEditor): string`:
   - Traverse the component tree from `editor.getWrapper()` (recurse `.components()`), collecting
     every component where `editor.Layers.isVisible(c) === false` into a `hidden` array.
   - If `hidden.length === 0`, return `editor.getHtml()` unchanged (fast path).
   - Otherwise: snapshot `const snapshot = editor.getProjectData()` BEFORE removal (the snapshot
     carries the display:none styles, so restoring it preserves eye state). Then, inside a
     `try { ... } finally { editor.loadProjectData(snapshot); }` block, call
     `hidden.forEach((c) => c.remove())` and `const mjml = editor.getHtml()`; return `mjml`.
     The finally guarantees the user's document (including hidden sections) is restored even if
     getHtml throws — never leave hidden sections permanently deleted.
   - Add a concise comment explaining WHY (display:none is not MJML-safe / Outlook-unreliable —
     see design_decisions + mjml-email-safety.md), so a future reader does not "simplify" it back
     to shipping display:none.
2. Wire `getExportMjml` into BOTH export paths so canvas === export everywhere: replace
   `editor.getHtml()` with `getExportMjml(editor)` in `compileDraft` and in `exportHtml`.
3. Create hooks/useLayerVisibility.ts exporting `useLayerVisibility(component: Component)`:
   - `const editor = useEditor()` from @grapesjs/react.
   - Local `useState` initialized from `editor.Layers.isVisible(component)`.
   - `useEffect` subscribes to `editor.on('component:toggled', handler)` where handler re-reads
     `editor.Layers.isVisible(component)` and setState; cleanup with `editor.off`. (Mirror
     useSelectedComponent.ts exactly.)
